第3条（第三者提供および委託先）

当社は、法令に基づく場合を除き、利用者の同意なく個人情報を第三者に提供・販売することはありません。

本サービスの提供にあたり、以下の外部サービスを情報の保管・処理の委託先として利用します。各社のプライバシーポリシーが適用されます。

  • Supabase（データベース・ファイル保管基盤。データは AWS 東京リージョンで保管）
  • Vercel（Web 版のホスティング・配信基盤）
  • Resend（認証コード・通知メールの送信）
  • Stripe（法人プランの決済処理）
  • Sentry（エラー監視。運営会社は米国。データの保存先は EU 圏内のリージョン）
  • Apple（iOS 版のプッシュ通知の配信基盤。Apple Push Notification service）
  • Google（Android 版のプッシュ通知の配信基盤。Firebase Cloud Messaging）

Sentry には、アプリや Web 版でエラーが起きたときに、エラーの種類、当社が定めた固定のエラーコード、プログラムのどの部分で起きたかを示す情報、アクセスされた機能の種類、実行環境の名称と版だけを送ります。利用者のメールアドレス・氏名、投稿内容、Cookie、操作履歴は送りません。Apple と Google には、通知を端末へ届けるために、端末トークンと通知の文言（何が起きたかを示す短い文）を渡します。質問の題名・本文は通知の文言に入れません。

これらの委託先のうち外国にある事業者については、第9条に所在国と各国の制度・各社の措置をまとめています。

公開された質問・回答は、本サービスの利用者および閲覧者に表示されます。これは利用者自身による公開であり、当社による第三者提供には該当しません。

第4条（広告・トラッキング）

本サービスは、広告配信および利用者の行動を追跡するトラッキングを行いません。第三者の広告 SDK・行動分析 SDK を組み込んでいません。

そのうえで、障害を早く見つけて直すこと、および通知を届けることのために、必要最小限の情報だけを外部のサービスへ送ります。具体的には、エラー監視のために Sentry へ送る情報と、プッシュ通知の配信のために Apple・Google へ渡す情報です。内容は第3条のとおりです。これらを広告や利用者の行動の分析に使うことはありません。

第5条（Cookie 等の利用）

Web 版では、ログイン状態の維持およびリクエスト改ざん防止（CSRF 対策）のために必要な Cookie のみを使用します。これらは本サービスの動作に不可欠なものであり、広告や行動分析の目的では使用しません。ブラウザの設定で Cookie を無効にした場合、ログインを要する機能は利用できません。

第6条（データの保管期間）

主なデータの保管期間は次のとおりです。

  • アカウント情報・投稿内容は、アカウントが存続する間、または利用者が削除するまで保管します。
  • 法人審査のために任意で提出された資料（名刺画像等）は、審査完了後 90 日以内に削除します。会社 URL は企業ページに表示するため、法人アカウントが存続する間保管します。法人番号・会社ドメインメールの認証記録は、認証状態の維持のため、法人アカウントが存続する間保管します。
  • 審査の結果が出ないまま 180 日が過ぎた申請は、取り下げたものとして扱い、提出された資料は取り下げ扱いの日から 90 日以内に削除します。
  • 資料のアップロードの手続を始めたものの、申請に登録されなかったファイルは、発行から 24 時間で削除します。
  • 認証コード（OTP）は発行から 10 分で失効します。失効または使用済みとなった記録は、不正利用の検知のために 3 日間だけ残し、その後に削除します。
  • ログインのセッションの記録は、有効期限が切れてから 7 日後に削除します。
  • 二重送信を防ぐための記録は、作成から 24 時間で削除します。
  • 企業ページの閲覧・クリックの集計用の記録（第2条の符号と日付）は、記録した日の翌日の終わりまで保管します。それより古い日付の記録は、次に新しい記録を書き込むときに削除します。集計後の日ごとの件数は、個人を特定できない数字として残ります。
  • 回数制限のための記録（送信元 IP アドレス・メールアドレス・利用者 ID と、操作の種類・時刻）は、作成から 2 日を過ぎたものを、同じ IP アドレス・メールアドレス・利用者による次の操作のときに削除します。
  • お問い合わせの記録（内容・連絡先・送信元 IP アドレス）は、対応を終えてから 3 年間保管し、その後に削除します。お問い合わせの本文に氏名・電話番号・メールアドレスなどが書かれていた場合も、その部分は本文と同じ期間保管し、本文とあわせて削除します。退会した方のお問い合わせも同じです。
  • 通報および運営による対応記録は、同種の問題への対応・再発防止のために必要な期間保管します。
  • 契約・決済に関する記録は、法令で定められた帳簿保存期間にわたり保管します。

バックアップには、上記の削除が反映されるまでに時間がかかる場合があります。

アカウントを削除したとき

利用者は、本サービス内の「アカウント削除」により、自身のアカウントおよび当社サーバー上の関連データの削除を請求できます。削除の操作をすると、次のように取り扱います。なお、法人の最後の管理者の方は、先に後任の方を管理者にしていただくまで、削除できません。

消去または匿名化するものは、メールアドレス（再び特定できない形に置き換え、同じアドレスで登録し直せるようにします）、ニックネーム・自己紹介・顔写真、回答者として公開していた氏名・役職、すべての端末のログイン、通知用の端末トークン、ご本人のメールアドレス宛ての認証コードの記録、ご本人のメールアドレス宛ての法人への招待に残っているメールアドレス、お問い合わせの連絡先として記録された氏名・電話番号・メールアドレス、二重送信防止の記録です。まだ公開されていない質問と回答（承認待ちのものを含みます）は削除します。公開済みの質問の投稿者名は「削除済みユーザー」に置き換えます。審査の結果が出ていない法人申請は取り下げ扱いとし、提出された資料は 90 日以内に削除します。

残すものは、公開済みの質問・回答の本文（投稿者との紐付けを解除したうえで、他の利用者の閲覧の継続性のために掲載を続ける場合があります）、法人における所属の変更の記録（所属は終了します）、お問い合わせの本文と送信元 IP アドレス（受付の記録として、対応を終えてから 3 年間保管し、その後に削除します。本文の中に書かれた氏名などは退会時には消さず、この期間が過ぎるまで残ります）、通報・運営による対応記録、法令に基づく契約・決済の記録、運営の操作記録（氏名・メールアドレスは含みません）です。投稿自体の削除を希望する場合は、第8条の窓口へ削除申請を行ってください。

第7条（安全管理措置）

当社は、取得した情報の漏えい・滅失・毀損を防止するため、以下の措置を講じます。

  • 通信の暗号化（TLS）
  • 認証コードおよびセッションの識別子をハッシュ化して保管し、平文では保存しないこと
  • 法人審査資料へのアクセスを、審査を担当する運営者のみに限定し、アクセスの都度記録を残すこと
  • 法人内の権限（管理者・回答者等）に応じたアクセス制御と、データベースにおける行単位のアクセス制限
  • 委託先の選定にあたり、安全管理体制を確認すること

各国の個人情報保護の制度

個人情報保護委員会は、外国における個人情報の保護に関する制度を、国ごとに公表しています。本サービスに関係する国のページは、次のとおりです。

  • 米国
  • シンガポール
  • インド（Stripe のデータの移転先として、同社が示している国です）

米国には、日本の個人情報保護法のような個人情報の取扱い全般を定める単一の連邦法はなく、分野ごとの連邦法と各州の法律で定められています。インドにも、同様に、個人情報の取扱い全般を定める包括的な法令はありません。シンガポールには、民間事業者を対象とする個人情報保護法（PDPA）があります。各国の制度の詳しい内容は、上記の個人情報保護委員会のページをご覧ください。

EU 加盟国には、GDPR（一般データ保護規則）があります。EU は、個人情報保護委員会により、日本と同等の水準の個人情報保護制度を持つ国として指定されています。

各事業者が講じる個人情報保護の措置

次の 4 社については、各社が公開しているデータ処理に関する契約条項（DPA）などに、次の措置が定められています。

  • Resend: 通信と保存データの暗号化。受け取った個人データを、当社の文書による指示またはこの契約条項の範囲でのみ第三者へ開示すること。再委託先を変更する場合は事前に通知すること。契約の終了後 90 日以内にデータを返却または削除すること。国外への移転には標準契約条項（SCC）を用いること。
  • Stripe: データの暗号化、アクセス制御、カード情報の保護基準（PCI-DSS レベル 1）への準拠。再委託先のアクセスを必要な範囲に限り、変更は事前に通知すること。国外への移転が必要な場合は、標準契約条項（SCC）などの移転の仕組みを用いること。
  • Vercel: 保存時と通信時の暗号化（AES-256・TLS 1.2 以上）、第三者機関による監査（SOC 2 Type 2）。顧客のデータを販売せず、第三者の自社の事業のために共有しないこと。再委託先にも同等のデータ保護の義務を課すこと。国外への移転には標準契約条項（SCC）を用いること。
  • Supabase: 保存時と通信時の暗号化（AES-256・TLS 1.2 以上）、必要最小限の権限によるアクセス管理、二要素認証、毎日の暗号化バックアップ。顧客のデータを販売せず、契約に基づく目的の外で使わないこと。再委託先を変更する場合は事前に通知すること。
